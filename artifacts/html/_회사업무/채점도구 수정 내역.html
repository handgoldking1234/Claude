작업 중 드러난 함정 3가지

채점도구 설정에서 비롯된 것들이라, 앞으로 이 안에서 작업할 때 같은 증상을 다시 만나게 됩니다.

1. 리셋이 Tailwind border 를 무력화한다

.grading-tool-shell button/input/textarea/select { border: 0 } 때문에 폼 요소에서만 border border-border 가 그려지지 않습니다. 실측: <div> 는 solid 1px, <button> 은 none 0px.

이번에 다섯 곳(임시저장 · 패널 손잡이 · 점수 버튼 · 확대 비율 · 평가요소 셀렉트)을 0-3-0 개별 규칙으로 우회했습니다. 아직 남은 곳: 코멘트 입력창과 취소 버튼 (AnnotationCanvas.tsx:1456, 1469). 원래부터 그랬던 자리입니다.

2. preflight: false 의 부작용

Tailwind 의 translate 유틸리티(-translate-x-1/2 등)가 전부 무효입니다 — --tw-translate-y 같은 기본값이 preflight 에 깔려 있어야 transform 선언이 성립합니다. 채점도구 안 4곳을 [transform:…] 로 바꿨고 지금은 남은 게 없습니다.

border-style 기본값이 none 인 것도 같은 뿌리로, 위 1번과 겹칩니다.

3. .hidden 이름 충돌

플랫폼 common.css:189 가 .hidden { visibility: hidden } 으로 정의합니다. Tailwind 의 hidden(display:none)과 이름이 같아, 맨 hidden 을 쓰면 요소가 자리는 차지한 채 안 보입니다. 실제로 PC 헤더가 이 때문에 비어 보였습니다.

변형 접두사가 붙은 sm:hidden·max-sm:hidden 은 클래스 이름이 달라 안전합니다. 현재 맨 hidden 사용처는 없습니다.

확인하지 못한 것 — ① eslint 미실행(패키지 없음) ② 답안 이동 묶음은 SMS 문맥에서만 렌더돼 실물 확인 불가(640px 경계는 시험용 요소로 간접 확인) ③ 다크모드에서 bg-amber-50(오류 배너 3곳)·bg-sky-50(안내 배너)는 라이트 전용으로 남음

제안 — 위 1번은 grading-tool.css 리셋에서 border: 0 을 빼면 개별 우회가 더 필요 없어집니다. 다만 채점도구 전체 버튼·입력에 영향이 가는 변경이라 이번엔 손대지 않았습니다.
