1. 잔여 작업 정의 및 우선순위

UI팀에 남은 작업은 크게 3가지.

구분 내용 일정
① 화면 수정·신규 화면 고객 컨펌 후 반영 요청분. 요청이 들어오면 항상 1순위 컨펌: 다음 주 금요일 대구 방문 → 그 다음 주 전달
② 다크 모드 RFP 항목(다중 모드 제공). 바닥에 깔고 가는 기본 작업 한 페이지 먼저 코딩 → 리뷰 후 전체 진행
③ 모바일 테이블(목록) 모바일 전용 템플릿 제작 감리는 현행 반응형으로 통과, 실사용자용 재작업은 10월까지
  • 프로젝트 공식 종료: 10월 말. 감리 10월 둘째 주경 시작.
  • 9월까지 전부 완료는 불가 → 두 사람이 다크모드/모바일을 나눠 맡을지 협의 후, 완료 가능 일정을 PL에게 전달. 일정이 맞지 않으면 재협의.
  • 고객 컨펌 미확정 화면: 평가 결과 리포트, 평가 시행(시행 관리), 커뮤니티/게시판. 신규 화면이므로 변경 가능성 있음. 다음 주 월요일은 고객 행사로 대구 방문 불가.

2. 다크 모드

  • 이미지 시안만으로는 적용이 어려움 → HTML로 공통 한 페이지를 잡고 그 기준으로 확산.
  • 고객 제공 PNG 샘플의 특징: 배경은 어둡게, 오브젝트(카드·패널)는 밝게 강약 대비. 색을 찍어 옮기는 방식이 아님.
  • 바디 영역 그라데이션은 전부 제거(모바일에서도 애매해짐). 이미 살려둔 상단만 유지.
  • 작업 후 다시 공유.

3. 모바일

  • 반응형은 전체 적용 완료, 테이블만 남음. 게시판형 화면이 전체의 70~80%.
  • 목록 테이블은 좌우 스크롤 방식 불가(사용성 저하). 행 단위 카드/박스형 모바일 전용 템플릿을 별도 제작.
  • RFP상 전 화면 대상이며 선택 적용 협의 시점은 지남 → 범위 축소 불가.
  • 탭이 많은 화면: 두 줄로 떨어지는 방식 X. 드롭다운/아코디언(카테고리 열고 닫기) 등으로 재고민, 샘플링 필요. 가로 스크롤 금지, 세로 스크롤은 감수.
  • 모바일 목록에서는 상세 버튼 없이 행 터치로 진입.
  • 브라우저 축소가 아니라 실제 디바이스에서 확인.

4. AI 검수 결과

  • 공통 작업 AI 검토 결과 버튼 379개 중 273개 미적용으로 표시 → 수치 신뢰 어려움.
  • URL 포함 엑셀 목록으로 뽑아 담당자가 무시/작업 여부 직접 판단.

5. 공통 UI 리뷰 — 수정 사항

작업 방식

  • 지금까지 한도인(조회성) 계정 위주로 확인 → 액터별 계정(교육청 업무 관리자 등)으로 로그인해 등록·수정·승인 화면 및 모달 창 전수 재점검. 메뉴 구조도의 액터(17개)별 표시 참고.
  • 권한 없는 메뉴가 "권한 없음"으로 뜨는 건 → 권한자 메뉴만 노출되도록(기획 확인).

목록 화면 (구조 확정)

  • 순서: 화면 설명 → 현황 섹션 → 조회 조건 → 목록 → 페이징/건수.
  • 상세 진입: '상세'(두 글자) 버튼으로 통일, 우측 액션 버튼 영역에 배치. 제목 클릭 진입도 병행 가능. '상세 보기' 표기 X.
  • 연합 상세의 '바로가기' 버튼 제거(중복).
  • 검색: 실시간 검색과 조회 버튼이 혼재 → 조회 버튼 방식으로 통일 원칙. 단, 현재 전체 데이터를 한 번에 불러와 클라이언트에서 페이징하는 구조로 보임 → 개발(혜리/이도) 확인 후 참석자4가 기준 확정.
  • 페이지네이션: 현행 형태 유지(처음/끝 버튼 없이), 센터 정렬 검토. 좌측 총 건수.
  • 상세 진입 후 목록 복귀 시 정렬 유지 → 개발(히스토리) 처리.
  • 목록 액터 번호(1, 2…) 컬럼 제거. 항목 내에서는 배지 형태로 감싸기.

상세·등록 화면

  • 연합 목록 상세 상단의 현황 카드/'구성 완료' 배지 구성은 어색 → 기획 확인 후 PL이 표현 방식 정리해 전달. (상세는 읽기 전용 성격, 현황은 목록/대시보드 쪽 요소)
  • 문항 설계 스텝 영역이 너무 넓음 → 50~60%로 축소, 박스 라인 제거하고 글자·바닥 색 변화만. 스크롤 버그 수정.
  • 등록 폼: 교과 선택 박스를 위로, 나머지를 아래로 배치해 빈 공간 제거.
  • 성취기준 항목이 많아질 때 패널 확장 확인.
  • 카운터 표시 오류(전체 8 / 선택 0) → 프로그램 확인.
  • 이동 버튼 문구는 "목록으로 이동"처럼 동사까지 명시. 순서: 아이콘 → 배지 → 버튼. 흰 바탕 버튼은 링크와 구분되게 색 채움.

배지·색상·메시지

  • 미선정 등은 버튼이 아니라 배지 → 같은 배지끼리 나란히 배치, 높이 통일.
  • 버튼 색상은 파란 계열로 통일 완료. 강조용 빨간(오렌지) 색은 노란 쪽에 가까운 오렌지로 조정.
  • 상세 헤더 그라데이션은 한 가지로 통일, 바디 그라데이션 제거.
  • 안내 메시지는 라인 없이 면만(경고/위험 등 다른 유형 포함 검토). 카드 라인 박스 남용 자제, 단절감 줄이기.
  • 조회조건과 목록 사이 안내 박스 → 제목 옆 느낌표 아이콘 툴팁으로 통합.
  • 스크롤 컨테이너는 아래 항목이 반쯤 걸치게 표현해 더 있음을 인지시키는 방식으로 통일.

기타

  • 알림: 시스템 푸시 메시지(예: "대표 교사로 선정되셨습니다", "채점 50% 진행") 전용. 채팅/쪽지 아님. 이의신청용 1:1 채팅은 별도 화면 구성 중. 알림 메시지 종류 정리 필요(PL).
  • 도움말 모달(AI 생성 화면)은 미사용. 도움말은 운영관리 > 공지/도움말에서 관리. 첨부 방식은 RFP 정의 참고.
  • 에디터: 디자인이 너무 올드하고 무료 라이선스 갱신 문제 → 도입 SW 목록 확인 후 오픈소스 WYSIWYG 대체 검토(PL). 퍼블리싱 책임 아님.
