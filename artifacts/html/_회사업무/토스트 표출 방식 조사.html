가장 빠른 길 — 가이드 페이지

/front-component에 토스트 예제 버튼 3개가 있습니다. 성공·오류·경고를 클릭 한 번으로 비교할 수 있습니다.

http://127.0.0.1:3100/front-component

아이콘 섹션의 아이콘 클릭으로도 “복사했습니다” 성공 토스트가 뜹니다.

실제 화면에서 띄우는 공통 패턴

  1. 저장·수정·삭제 완료 — 대부분의 성공 토스트
  2. 필수값 비우고 제출 — 경고 토스트
  3. 복사 버튼 — 코드·링크 복사 시 성공 토스트
  4. Excel 내려받기 — 다운로드 완료 성공 토스트

토스트는 화면 상단 중앙에 고정되고 4초 뒤 자동으로 사라집니다. 닫기 버튼으로 즉시 닫을 수도 있습니다.

이 3화면은 warn이 맞습니다

전부 사용자 입력을 안내하는 문구입니다. 시스템이 실패한 게 아니라 채워야 할 값을 알려주는 것이므로 노란 경고가 맞습니다. show('제목을 입력해 주세요.') → show('제목을 입력해 주세요.', 'warn') 한 줄이면 됩니다.

세 가지 표출 방식

① 공통 ToastBanner 31화면

상단 중앙 고정 · 4초 자동 소멸 · 닫기 버튼 · role="alert". 색은 인라인 스타일로 박혀 있어 CSS로 못 바꿉니다 — --ui-success / --ui-danger / --ui-warn 토큰을 씁니다.

② permission-toast 전용 CSS 2화면

권한 신청·검토 2화면만 자체 구현입니다. 공통 훅을 안 쓰고 로컬 showToast와 _04-ops-permissions.scss의 전용 클래스를 씁니다.

  • /permissions/requests/new — 임시저장 · 신청 제출
  • /permissions/requests/{id}/review — 승인 · 반려 · 이력 조회

타입 구분이 없습니다 — 항상 체크 아이콘 하나로만 뜹니다.

③ 브라우저 window.alert 11파일

토스트가 아니라 브라우저 기본 팝업입니다. 화면을 막고, 확인을 눌러야 사라지고, 디자인을 전혀 적용할 수 없습니다. 자동으로 사라지지도 않습니다.

같은 방식인데 색이 갈리는 이유

ToastBanner 자체는 화면마다 동일합니다. 달라 보이는 건 호출할 때 타입을 뭘로 넘기느냐의 문제입니다. 같은 성격의 안내인데 어떤 화면은 warn, 어떤 화면은 타입 생략(→빨강)으로 되어 있습니다.

정리 제안

1순위 — 타입 생략 5곳 지금 어색함

커뮤니티 3화면의 입력 안내가 빨간 오류로 뜹니다. 'warn'을 넘기면 끝나고, 퍼블 범위 안이라 바로 처리할 수 있습니다.

2순위 — permission-toast 2화면

공통 ToastBanner로 바꾸면 위치·소멸시간·닫기 버튼·타입 색이 다른 화면과 같아집니다. 로컬 showToast를 useToast로 교체하는 작업이라 상태 로직을 건드립니다 — 확인이 필요합니다.

3순위 — window.alert 11파일

토스트로 바꾸면 화면을 막지 않고 디자인도 통일됩니다. 다만 alert은 사용자가 확인을 누를 때까지 다음 코드가 멈추는 동작이라, 그대로 바꾸면 흐름이 달라질 수 있습니다. 로직 담당자와 함께 봐야 합니다.

검토해 볼 것 — 기본값

useToast의 기본 타입이 'error'인 것 자체가 사고를 부릅니다. 타입을 필수 인자로 바꾸면 앞으로 빠뜨릴 수 없습니다. 공통 훅 변경이라 합의가 필요합니다.
