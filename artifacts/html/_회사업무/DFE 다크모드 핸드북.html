DFE 다크모드 핸드북

이전 작업자가 남긴 것은 “CSS와 부분 수정”이 아니라 토큰 아키텍처 전환이다. 이 문서는 그 구조가 실제로 어떻게 동작하는지, 어디까지 되어 있는지, 그리고 화면 하나를 다크 대응시키려면 무엇을 해야 하는지를 정리한다.

01 — 무엇이 화면을 바꾸는가

다크모드는 CSS 미디어쿼리(prefers-color-scheme)가 아니라 <html data-theme="dark"> 속성 하나로 동작한다. 사용자가 OS를 다크로 바꿔도 앱은 반응하지 않는다 — 오직 사이드바의 테마 선택만이 바꾼다.

파일역할
src/shared/hooks/useTheme.ts applyTheme()가 documentElement에 data-theme를 심는다. 선택값은 localStorage["dfe_theme:{userId}"]에 사용자별로 저장되고, 같은 탭 동기화는 dfe:theme-changed 커스텀 이벤트로 이뤄진다.
src/main.tsx 부팅 시 applyTheme(readStoredTheme()) 1회. 로그인 전에는 guest 키를 읽는다.
src/app/MainLayout.tsx 로그인 사용자가 확정되면 useTheme(userId)로 다시 구독해 사용자 키 기준으로 재적용한다.
src/app/MainAside.tsx 테마 선택 팝오버 UI. 사용자가 실제로 테마를 바꾸는 유일한 지점이다.
등록된 테마

useTheme.ts의 AVAILABLE_THEMES에는 light · dark · blue(시그니처) 3개가 노출돼 있다. 하지만 theme.scss에서 실제 내용이 있는 것은 dark 뿐이다 — [data-theme="light"]는 빈 블록이고(=:root 기본값이 곧 라이트), [data-theme="blue"]와 [data-theme="signature"]는 스크롤바 색 2줄짜리 껍데기다. 지금 “테마 작업”은 사실상 다크 하나를 채우는 일이다.

02 — 토큰 3층 구조

이번 머지의 본질은 원시 색과 의미 색의 분리다. 예전에는 _tokens.scss 하나에 #2d76f7도 --ui-primary도 섞여 있었지만, 지금은 층이 나뉘어 있고 다크 오버라이드는 가운데 층에서만 일어난다.

_tokens.scss 원시 팔레트. --blue-03, --gray-cool-27처럼 이름이 색 그 자체다. 여기엔 다크/라이트 개념이 없고, 값은 절대 바뀌지 않는다.
→
theme.scss :root 의미 토큰. --ui-primary: var(--blue-03). 컴포넌트가 참조해야 하는 유일한 층이다. 이 블록이 곧 라이트 테마다.
→
theme.scss [data-theme="dark"] 다크에서 달라져야 하는 의미 토큰만 재정의. 141개 중 74개만 여기 들어 있다.

로드 순서는 src/shared/styles/styles.scss가 강제한다. @use 'theme'가 global/*보다 먼저 와야 캐스케이드가 성립하므로, 이 파일의 import 순서는 건드리지 않는다(파일 상단 주석에도 명시돼 있다). 

// src/shared/styles/styles.scss
@use 'theme' as *;        ← 반드시 첫 줄

@use 'global/00-base' as *;
@use 'global/02-ui-components' as *;
…
자주 하는 실수

컴포넌트 CSS에서 var(--blue-10)처럼 팔레트를 직접 참조하는 것. 팔레트는 테마와 무관하게 고정이므로 다크에서 그대로 밝은 하늘색이 남는다. 컴포넌트는 항상 의미 토큰(--ui-*, --ok-*, --info-*)만 쓴다.

03 — 핵심 규칙: -theme 접미사

이 코드베이스에서 가장 중요한 관습이자, 모르면 반드시 버그를 내는 규칙이다. 같은 색에 대해 토큰이 두 벌 존재한다.

--ui-primary-weak는 라이트 값에 고정되고, --ui-primary-weak-theme는 다크에서 뒤집힌다. 고정형이 필요한 이유는 다크에서도 흰 배경을 유지해야 하는 자리(인쇄용 영역, 항상 밝은 카드 등)가 있기 때문이다.

배경·연한 채움·테두리에 색을 줄 때는 -theme 쪽을 쓴다. 아래가 검증된 전체 짝 목록이다.

고정형 (다크에서 안 바뀜) 테마형 (다크에서 바뀜) — 이걸 쓴다 다크 값
--ui-bg--ui-bg-themergba(255,255,255,.06)
--ui-primary-weak--ui-primary-weak-themergba(147,197,253,.1)
--ui-warn-weak--ui-warn-weak-themergba(242,116,58,.08)
--ok-soft--ok-soft-themergba(187,247,208,.08)
--info--info-themevar(--blue-04)
--info-bg--info-bg-themevar(--blue-02-04)
--info-line--info-line-themevar(--blue-03-04)
--ui-success--ui-success-themevar(--mint-26)
--ui-primary-light-border--ui-primary-light-border-themevar(--blue-02)
--ui-bg-muted-dark--ui-bg-muted-dark-themergba(255,255,255,.10)

--ui-success에는 짝이 셋 더 있다 — --ui-success-bg-theme(면), --ui-success-border-theme(선). 성공 상태 카드를 만들 때는 이 둘을 쓴다.

직접 확인하기

아래 스와치는 제품의 실제 토큰 값을 복제한 것이다. 이 페이지를 다크로 보면 왼쪽은 색이 바뀌고 오른쪽 두 개는 밝은 채로 남는다 — 그게 함정의 실체다.

--ui-surface
다크 오버라이드 있음 테마를 따라 뒤집힌다. 안전하게 써도 된다.
--ui-primary-weak-theme
테마형 다크에서 반투명 블루로 바뀐다.
--ui-primary-weak
고정형 — 함정 다크에서도 #eff6ff. 어두운 화면에 밝은 사각형이 남는다.
--ok-soft
고정형 — 함정 #bfd4f7 그대로. --ok-soft-theme를 써야 한다.

05 — 화면 하나 대응 절차

전체를 한 번에 하지 않는다. 화면(=CSS 파일) 단위로 끊어서 처리하는 것이 이 코드베이스에서 검증된 방식이다.

  1. 대상 파일의 하드코딩 색을 전부 뽑는다

    화면 하나의 CSS/SCSS에서 남은 리터럴 색을 먼저 센다. 개수가 곧 작업량이다.

    git grep -o -E '#[0-9a-fA-F]{3,8}\b' -- 'src/features/<대상>/**' | sort | uniq -c | sort -rn

  2. 팔레트에 같은 값이 있는지 먼저 찾는다

    _tokens.scss의 팔레트 항목 대부분에는 // --ui-warn-border 같은 역참조 주석이 달려 있다. 그 주석이 “이 원시 색은 어떤 의미 토큰으로 쓰이는가”를 알려주므로, 리터럴 → 의미 토큰 매핑은 대개 여기서 바로 나온다. 

    // _tokens.scss — 역참조 주석이 매핑표 역할을 한다
--orange-06: #e9c29c;  // --ui-warn-border
--gray-cool-14: #64748b;  // --theme-text-muted, --ui-text-muted

  3. 면·선은 -theme 토큰으로, 글자는 일반 토큰으로

    background·border-color는 03·04장의 짝 표를 보고 -theme 쪽을 고른다. color는 --ui-text 계열이 이미 다크 대응돼 있으니 그대로 쓴다. 

    - background: #eff6ff;
+ background: var(--ui-primary-weak-theme);

- color: #4a585f;
+ color: var(--ui-text-sub);

  4. 토큰으로 안 되는 자투리는 파일 끝에 다크 블록으로

    그라디언트, 특수 오버레이처럼 토큰 한 개로 표현 안 되는 것들이 남는다. 이때는 파일 맨 아래에 [data-theme="dark"] 블록을 모아서 둔다. 선례는 union-teacher-assign-dialog.css(7곳)와 _09-page-components.scss(21곳)다. 규칙 하나: 다크 블록을 파일 곳곳에 흩지 말고 한 군데에 모은다. 

    /* ── dark theme overrides ─────────────────── */
[data-theme="dark"] .union-teacher-assign__teacher-list,
[data-theme="dark"] .union-teacher-assign__subject-options label {
  background: var(--ui-bg);
}

  5. 라이트 전용 장식 블록은 지우지 말고 주석 처리

    하드코딩 색으로 범벅이라 다크에서 살릴 수 없는 블록은 //로 주석 처리해 남긴다(삭제하지 않는다). 이전 작업자가 _09-page-components.scss의 .user-role-* 19줄에 이 방식을 썼다. 지우면 나중에 복원 근거가 사라진다.

  6. 두 테마 모두 눈으로 보고 빌드한다

    사이드바 테마 팝오버로 라이트↔다크를 왕복하며 확인한다. SCSS 오타는 dev 서버 HMR에서 조용히 넘어가는 경우가 있으므로 빌드까지 돌린다. 

    npm run dev          # 127.0.0.1:3100, 사이드바에서 테마 전환
npx tsc -b           # 타입
npx vite build --mode development   # SCSS 컴파일 실검증

06 — 현재 진행 상황

“부분 수정”이라는 표현은 정확하다. 공통 레이어(사이드바·헤더·패널·버튼·테이블)는 끝났고, 개별 업무 화면은 대부분 손대지 않았다.

토큰만 사용 42 / 112 하드코딩 색 잔존 70 파일 남은 리터럴 색 3,744개 다크 오버라이드 74 / 141 토큰

다음은 남은 리터럴 색이 많은 순이다. 위에서부터 잡는 것이 비용 대비 효과가 가장 크다.

07 — 지금 남아 있는 결함

머지된 theme.scss를 정적 검사해 확인한 실제 결함 2건이다. 둘 다 짧게 고칠 수 있다.

1 · 정의되지 않은 변수 참조

theme.scss:299에서 --ui-tbody-hover-bg: var(--alpha-light-01)을 쓰는데, 팔레트에는 --alpha-light-03 / -06 / -08 / -10만 있고 --alpha-light-01은 정의되어 있지 않다. 결과적으로 다크모드에서 테이블 행 hover 배경이 아예 적용되지 않는다. --alpha-light-03으로 바꾸거나 팔레트에 --alpha-light-01: rgba(255,255,255,.01)을 추가해야 한다.

2 · 토큰명 오타

--ui-bg-mint-lignt — light의 오타다(theme.scss:103, :281 2곳). 지금은 정의·참조가 같은 오타라 동작은 하지만, 나중에 올바른 철자로 쓰면 조용히 실패한다. 사용처가 아직 없을 때 지금 고치는 것이 가장 싸다.

08 — 리뷰 체크리스트

다크모드 관련 변경을 리뷰할 때 이 여섯 개만 확인하면 대부분 걸러진다.

  • 새로 추가된 CSS에 #으로 시작하는 리터럴 색이 없는가
  • var(--blue-*), var(--gray-cool-*)처럼 팔레트를 직접 참조한 곳이 없는가
  • background·border-color가 04장 “안 바뀌는 토큰” 목록에 있는 것을 쓰지 않았는가
  • [data-theme="dark"] 블록이 파일 곳곳에 흩어지지 않고 한 군데에 모여 있는가
  • 라이트 전용 블록을 삭제하지 않고 주석 처리했는가
  • 라이트·다크 양쪽 스크린샷이 있는가 (한쪽만 보고 머지하면 반드시 새는 곳이 생긴다)
한 줄 요약

팔레트는 _tokens.scss, 의미는 theme.scss, 컴포넌트는 의미 토큰만 — 그리고 면을 칠할 땐 -theme 접미사를 확인한다.

조사 근거: theme.scss(340줄) · _tokens.scss · styles.scss · useTheme.ts 정적 분석, src 하위 스타일 파일 112개 전수 스캔.
수치는 origin/feature/front-darkmode 머지 직후 작업 트리 기준이며, 후속 작업에 따라 달라진다.
