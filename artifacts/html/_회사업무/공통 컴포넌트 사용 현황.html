우선순위 제안

1. rightwrite 교사 화면 — Panel 117곳

전체 .ui-panel 직접 사용의 대부분이 여기 있습니다. 한 기능이 통째로 공통 컴포넌트를 안 타고 있어서, 이 기능만 정리해도 수치가 크게 달라집니다.

다만 화면 수가 많고 레이아웃이 다른 기능과 달라, 한 화면씩 확인하며 가는 편이 안전합니다. 대시보드나 목록 화면 하나로 먼저 해보고 판단하는 것을 권합니다.

2. HelpBanner — 10개 파일

내부표준화·평가설계 두 기능에 몰려 있고, 배너는 구조가 단순해 치환 위험이 낮습니다. 가장 먼저 손대기 좋은 대상입니다.

3. Modal — 16개 파일

ESC 닫기·포커스 트랩·스크롤 잠금이 파일마다 다르게 구현돼 있을 수 있어, 접근성 관점에서 정리 가치가 큽니다. 다만 각 모달의 동작을 확인하며 옮겨야 해 시간이 걸립니다.

4. 미사용 3개 — 결정 필요

Tabs · SubTabs 는 BoxTabs 와 역할이 겹칩니다. 셋 중 무엇을 언제 쓰는지 가이드에 명시하거나, 안 쓰는 둘을 지워야 합니다.

BackdropLoading 은 로딩 표현이 화면마다 제각각인 상태라 쓰는 쪽을 권합니다.

덧 — 라우트가 없는 화면

조사 중 라우트가 등록되지 않았거나 주석 처리된 화면이 여럿 나왔습니다. 역할 관리(RolesPage 주석 처리), 액터 유형 관리, 내부표준화 목록 구버전입니다.

공통화 대상에서 뺄지, 라우트를 살릴지 먼저 정하는 게 좋겠습니다. 안 보이는 화면을 고치는 건 낭비입니다.

수치는 import 경로 기준(@/shared/components/common/…)이며 컴포넌트 자기 자신과 가이드 화면은 분리해 셌습니다. 직접 조립은 해당 CSS 클래스를 마크업에서 직접 쓴 곳을 센 것으로, 파일 단위가 아니라 출현 횟수입니다.
