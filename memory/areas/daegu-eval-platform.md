- 대규모 어드민 SaaS (~60 HTML 페이지, 14,000+줄 스타일시트)
- CSS 리팩토링: BEM 컴포넌트, CSS 변수, 페이지 범위 선택자·nth-child 제거
- 구조: publishing/(HTML) / src/(React 이관)
- Claude Code 워크플로: 수정 전 diff 미리보기 패턴, CLAUDE.md·HANDOFF.md 작성, Claude Code·Claude Design 세션 시작 프롬프트 템플릿
- 서비스명 DEPTH, 라이트/다크 테마 토글 어드민
- 고객이 다크모드에 여러 색상 요청 — 지저분해질 우려로 상담; 다크모드 리밸런싱(주색 채도 -20%, 테이블 버튼 고스트화, 문항 버튼은 선택 1개만 solid·나머지 틴트)
- 기간 2025.12 ~ 2026.10, 디자인·퍼블 담당, 발주 대구시 교육청 (경력기술서 기준)
- 주색 그린 → 블루 변경(Teal→blue 마이그레이션), dark mode 브랜치를 feature/front-goldking에 머지
- 우측 설정 패널 HTML 퍼블리싱(멀티 인스턴스 충돌 방지 자동 네임스페이스)
- 단위테스트(QA): 사용자/관리자 화면별 수행, 결과를 단위테스트 계획서 엑셀에 기록
- 개발 테스트 접속: status=0 개발자 모드, 역할별 계정 test-01~test-12 / 1234 (test-01=교육청시스템관리자 … test-09=학생, test-12=채점교사), 개발용 Master 계정
- 최종 성과: 180페이지 넘는 화면 UI 통일, 반응형·웹표준·웹접근성, 관련 문서 작성·제출, 디자인·퍼블+프론트까지 — 감리 통과(2026-10), 본인 담당 지적 9건 정도
- 합류 당시 개발만 진행·UI 미정리 — 9월 말 화면 개선 → 반응형 → 감리 직전 웹접근성까지 거의 전담, 감리 문서 직접 작성
- 작업물은 날짜별 업로드 기록 있음 (AI로 작업 돌려두고 퇴근 후 집에서 검수·업로드)
- 8월 이전엔 개발 미완성으로 디자인할 거리가 없었는데 대구팀이 본인이 일을 안 한다는 식으로 보고한 것으로 봄; 대구팀이 자체 구축하다 결국 UI/UX 인력 필요로 8월 이후 합류
- 채점 도구 화면 개선 주도 제안 — 개발 쪽 반발로 색상·아이콘만 되돌림
- 감리 직전 기획 쪽이 모든 테이블 모바일 반응형 요구 — 과하다 의견 냈으나 전 페이지 완료, 이후 기획이 "그렇게까지 할 필요 없었다"고 함
- 웹접근성: 기획·개발은 라벨만 하면 된다 했으나 부족하다고 판단해 알아서 처리, 감리가 더 엄격했지만 통과
- 프론트는 처음 — 개발 소스 내 화면·CSS·반응형까지, 서버 접속·API 연동은 안 해봄
- 대구 현장에서 정해진 본인 역할: "프론트를 도와라"; 브루스는 UX본부처럼 주도하길 바랐던 듯 — 서포트 방향을 미리 상의하지 않은 게 패착이라고 판단
- 브루스가 AI 구독으로 프로토타입 기획·디자인·프론트 전달까지 혼자 하라 지시 → 결국 기획자·프론트 2명 투입 → 일손 부족으로 골드킹도 투입 (AI 쓰면서도 3명 필요했던 일)
- AI로 평가하는 플랫폼이어서 구축도 AI를 최대한 활용 (지원서 표현)
